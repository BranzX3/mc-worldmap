# ทิศทางโปรเจกต์: โลกที่อยากเดินเข้าไปสำรวจ

วันที่กำหนดทิศทาง: 2026-09-10 · ปรับลำดับงาน 2026-09-14: ระบบน้ำ greenfield
ยังไม่ผ่าน acceptance ในเกม

## เป้าหมายเดียวที่ใช้ตัดสินงาน

สร้างภูมิประเทศ Salzkammergut ใน Minecraft สำหรับ MMORPG ที่ผู้เล่น **อ่านพื้นที่ออก
เดินสำรวจได้ และอยากไปต่อเพราะสิ่งที่เห็นในโลก** น้ำ ธรณี ป่า ทุ่ง และจุดค้นพบ
ต้องประกอบเป็นสถานที่เดียวกันอย่างมีเหตุผล

ผลส่งมอบด้านประสบการณ์คือ **Immersion Slice v1: เส้นทางสำรวจต่อเนื่อง 10–15 นาทีในโลกจริง**
ที่ผ่านเกณฑ์ด้านล่าง ก่อนขยายคุณภาพนั้นไปทั้งแผนที่ งานปัจจุบันคือเขียนระบบน้ำ
ใหม่ให้มีฐานที่ตรวจสอบได้ก่อนนำไปประกอบเส้นทาง เวลาและจำนวนจุดค้นพบเป็น
เป้าหมายออกแบบเริ่มต้น ไม่ใช่ค่าที่วัดได้แล้วหรือข้อสรุปทางวิทยาศาสตร์

โปรเจกต์ยังคงพื้นที่ 40 × 40 km, 4 เมตรจริงต่อบล็อกทั้งแนวนอนและแนวตั้งตาม
`config.py` การรักษาสัดส่วนนี้ไม่ได้แปลว่าใช้สเกล 1 เมตรต่อ 1 บล็อก และไม่ได้
รับประกันว่าทุกทางลาดจะเดินสนุก ต้องทดสอบการเคลื่อนที่ในสเกลผู้เล่นแยกต่างหาก
พัฒนาและตรวจบนเครื่อง local เท่านั้น

## การตัดสินใจปัจจุบัน — ระบบน้ำใหม่

เจ้าของโปรเจกต์ให้เริ่มน้ำแบบ greenfield เพราะการแก้ logic เดิมสะสมไม่ให้
คุณภาพที่ต้องการ โค้ดใหม่อยู่ใน `water_v2/` ใช้ `terrain_y.npy` และ
`water_sources.npz` เป็นข้อมูลตั้งต้น แล้วสร้าง topology, route ใน corridor,
แก้ระดับร่วมบนกราฟ และส่ง geometry/material/fluid/plant เป็น product เดียว
ให้ block sink วางตามคำตอบ ดูสัญญาใน [WATER_V2.md](WATER_V2.md)

ขอบเขตปัจจุบันคือ `bounded_scene`; การ compile ผ่านไม่ใช่การรับรองทั้งโลก
และไม่ใช่หลักฐานว่าน้ำจะคงสภาพหลังเกม tick ข้อมูลจริงยังมี physical gates
ที่ไม่ผ่าน จึงยังไม่มีการเขียนระบบใหม่นี้ลงเซฟ รายงานและจำนวน tests จริงอยู่ใน
[ผลตรวจรอบระบบน้ำใหม่](reviews/water_v2_20260914.md)

ระบบน้ำเดิมและ `paint_ready_20260913_v3` เป็นหลักฐานย้อนหลัง เก็บไว้เทียบ
อาการและตรวจผลกระทบต่อส่วนอื่น แต่ไม่เป็น implementation หรือเกณฑ์บังคับ
รูปแบบน้ำใหม่ เซฟ **mc-worldmap Paint Test 2026-09-13** ยังเป็นระบบเก่า
การเปิดเซฟนั้นจึงไม่ใช่การทดสอบ rewrite

## Immersion ที่ต้องส่งมอบ

| เสาหลัก | ผู้เล่นต้องสัมผัสอะไร | หลักฐานผ่าน Slice v1 |
|---|---|---|
| สถานที่มีเหตุผล | น้ำลงสู่ที่ต่ำ ฝั่ง/หิน/พืชเปลี่ยนสัมพันธ์กับพื้นที่ | ฉากน้ำอย่างน้อยหนึ่งช่วงและ forest–meadow transition หนึ่งช่วง ไม่มี defect ระดับ blocker/major |
| เดินทางและอ่านทางได้ | มองเห็นทางไปต่อหรือจุดหมายระหว่างเดิน | เดินเส้นทางต้น–ปลายได้ครบ ไม่บิน/teleport/วางหรือทุบบล็อกช่วย ไม่มีจุดติดโดยไม่ตั้งใจ |
| อยากสำรวจต่อ | เห็นสิ่งชวนเข้าใกล้แล้วมีพื้นที่ให้เข้าไปจริง | จุดค้นพบอย่างน้อย 3 จุดต่างบทบาท: จุดหมายที่มองเห็น, จุดแวะ/ที่กำบังที่เข้าได้, จุดปฏิสัมพันธ์กับภูมิประเทศ เช่น ทางข้ามหรือทางลงน้ำ |
| รายละเอียดต่อเนื่อง | ไม่มีผิว/ต้นไม้/น้ำที่เผยให้เห็นขอบการ generate อย่างชัดเจน | ภาพระดับสายตาจากอย่างน้อย 6 จุดคงที่ พร้อมตรวจ object คร่อม region และช่วงรอยต่อ |

จุดค้นพบใช้สิ่งธรรมชาติที่มีอยู่ได้ ไม่บังคับสร้างอาคารหรือระบบรางวัลใหม่
วัตถุสามชิ้นที่เหมือนกันไม่ถือเป็นสามบทบาท เส้นทางไม่จำเป็นต้องเป็นถนนที่ทาสี
แต่ต้องให้ผู้เล่นเข้าใจว่าผ่านได้และมุ่งไปไหน

การรับรองหนึ่งรอบต้องมีทั้ง **ความถูกต้องของบล็อก/ข้อมูล** และ **การเดินกับ
ภาพระดับสายตา** แยกกัน ตัวเลขสวยชดเชยทางตันไม่ได้ และภาพสวยชดเชยน้ำลอยไม่ได้
เกณฑ์เทคนิคอ้าง [IMMERSION_SPEC.md](IMMERSION_SPEC.md); รูปแบบหลักฐานอ้าง
[IMMERSION_REVIEW.md](IMMERSION_REVIEW.md)

## ขอบเขตและข้อแลกเปลี่ยน

**อยู่ใน Slice v1:** terrain/water ที่เชื่อถือได้, forest–meadow coherence,
route ที่เดินได้, ทางข้าม/ทางลงน้ำตามความจำเป็น, จุดชมวิว/ที่กำบังระดับผิว,
การตรวจบล็อกและการเดินเกม ที่กำบังใช้รูปทรงธรรมชาติที่มีอยู่ได้; ถ้าใช้
`--shelters` ต้องผ่าน gate ของโพรงก่อน

**พักไว้จนกว่า slice ผ่าน:** arête/glacier detail ที่อยู่นอกเส้นทาง,
ชนิดพืชหรือ noise layer เพิ่มเติมที่ไม่แก้ defect บนเส้นทาง, ระบบถ้ำใต้ดินยาว,
การตกแต่งทั่ว 10,000² บล็อก และการย้ายโครงสร้างไฟล์ครั้งใหญ่เพื่อความเรียบร้อย
feature ที่มีแล้วให้ประเมิน/เก็บหลักฐานก่อนสร้างเพิ่ม

**อยู่นอก milestone นี้:** quest, combat, economy, NPC, lifeskill และระบบสัตว์
เป็นผู้ใช้ภูมิประเทศในอนาคตตามบริบท MMO ใน PIPELINE; repo นี้รับผิดชอบพื้นที่
และ affordance ทางกายภาพก่อน ไม่อนุมานว่าเป็นระบบ MMO ที่พัฒนาเสร็จแล้ว
shader/resource pack และเสียงไม่ใช้กลบ defect ของพื้นที่; ตรึง client settings
ตอนรีวิว หากภายหลังต้องใช้ให้แยกเป็น milestone พร้อม acceptance ของตนเอง

ลำดับตัดสินเมื่อขัดกัน: ความปลอดภัยของ save → ความต่อเนื่องที่จำเป็นต่อการเดิน
→ เอกลักษณ์/เหตุผลของภูมิประเทศ → รายละเอียดภาพ → การขยายพื้นที่/ความเร็ว
คงหน้าผาธรรมชาติที่ทำหน้าที่เป็นอุปสรรคไว้ พร้อมทางอ้อมหรือทางลงที่ตั้งใจไว้
ไม่ลดความชันทั้งโลกเพื่อบังคับให้ทุก cell เดินได้

## เป้าหมายตามระยะและจุดหยุด

| ระยะ | ผลส่งมอบ | เกณฑ์จบ | ถ้าไม่ผ่าน |
|---|---|---|---|
| M0 — baseline ที่ตรวจซ้ำได้ | runtime ใช้งานจริง + ระบุ code/input/config + ผล golden ปัจจุบัน | suite ผ่านด้วย dependency จริง, 11 patches มีผลครบ, ระบุ defect/หลักฐานเก่าได้; preflight พร้อมก่อนเขียนโลก | แก้ environment/provenance ที่ขวางการพิสูจน์ ไม่เพิ่ม decoration |
| W1 — compiler น้ำใหม่ | topology/router, shared level solver และ product ที่ระบุบล็อกครบ | ทดสอบสัญญาพฤติกรรมและ provenance ได้; รายงานข้อจำกัดที่ขัดกันพร้อมพิกัด; ไม่มี hidden dependency ต่อ logic น้ำเก่า | แก้การเชื่อมต่อ/สมการ/สัญญา ไม่อุดตลิ่งหรือขุดลึกเพื่อกลบ error |
| W2 — คุณภาพบนข้อมูลจริง | scene ตัวแทนจาก DEM/OSM เดิมที่ compile ผ่านข้อจำกัดทางกายภาพ | ปากน้ำ จุดบรรจบ ลำธารชัน และฉากอ้างอิงไม่มี physical violation; topology/ระดับ/ความลึก/แหล่งจ่ายน้ำสมเหตุผล | แก้กฎจากสาเหตุที่ทำซ้ำได้ ไม่ waive diagnostics หรือแก้เฉพาะพิกัดให้ผ่าน |
| W3 / M1 — น้ำในโลกจริง | writer ใหม่ที่วางตาม product, reopen/readback และฉากเดินตรวจ | บล็อกและ fluid state ตรง product; เปิดโลกและรอน้ำ tick แล้วไม่มี blocker/major; เจ้าของโปรเจกต์รับรองภาพ | แก้ product หรือ writer ตามหลักฐาน; ยังไม่รับรอง M1 จาก compile/tests อย่างเดียว |
| M2 — Immersion Slice v1 | เส้นทางต่อเนื่อง 10–15 นาที พร้อม ecosystem และ 3 จุดค้นพบ | ผ่าน 4 เสาหลัก, 6 จุดภาพ, blocker/major = 0, เจ้าของโปรเจกต์รับรองหลังเดินจริง | แก้ฉาก/เส้นทางเดิม ห้ามขยายพื้นที่เพื่อเลี่ยงจุดที่ไม่ผ่าน |
| M3 — ทำซ้ำแล้วขยายทั้งโลก | นำกฎเดียวกันไปใช้พื้นที่อิสระอย่างน้อย 2 แห่ง แล้วสร้าง global candidate | พื้นที่ใหม่ไม่ต้องแก้พิกัดเฉพาะจุดเพื่อผ่าน; global verifier ผ่าน; seam/readback และ walkthrough ตัวแทนผ่านจาก candidate เดียวกัน | กลับไปแก้กฎหรือประกาศ scope ที่ยังไม่รองรับก่อน build ทั้งใบซ้ำ |

ลำดับปัจจุบันคือ W1 → W2 → W3 → M2 → M3 โดย W1–W3 แทนงานน้ำ M1 เดิม
งานสำรวจ/เลือก route ทำควบคู่ได้ แต่การรับรอง M2 ต้องใช้บล็อกที่ผ่าน W3
ในพื้นที่นั้น ไม่ต้องตกแต่งทุกภูเขาหรือรับรองน้ำทั้งโลกก่อนเริ่ม slice

ผู้สมัครเส้นทางแรกคือกลุ่ม `player_liked (6165,6068)`,
`prototype_stream (6021,6142)`, `lake_corridor (6066,5811)` และ
`floodplain_berm (5970,5902)` เพราะอยู่ใกล้กันและมีจุดที่ผู้ใช้เคยชอบ
นี่เป็น **พื้นที่สำรวจเพื่อเลือก route** ไม่ใช่คำยืนยันว่าทั้งสี่จุดเดินเชื่อมกันแล้ว
สำรวจ slope/landcover และเกมจริงก่อนตรึงแนวทาง; ถ้าไม่ครบ forest–meadow ให้เลือก
ช่วงข้างเคียงจากข้อมูลจริง ส่วน `lake_mouth` และ `hill_junction` เป็น regression
patches แยกต่างหาก ไม่รวมจุดไกลกันด้วย teleport แล้วเรียกว่าเส้นทางต่อเนื่อง

## วิธีควบคุมงานตั้งแต่รอบถัดไป

1. มีงาน implementation หลักที่กำลังทำเพียงหนึ่งเรื่อง และคิวรอ world review
   ไม่เกินหนึ่งชุด งานใดยังรอหลักฐานให้เขียนว่า implemented/awaiting evidence
   ไม่ใช้คำว่าเสร็จ
2. ทุกงานระบุปัญหาที่ผู้เล่นเจอ, milestone, พิกัดหรือ artifact ที่ทำซ้ำได้,
   ผลที่คาด, และเกณฑ์จบ ก่อนเริ่มแก้ งานที่ผูกไม่ได้ให้อยู่ backlog
3. งานใหม่ต้องช่วยปิด gate ปัจจุบันหรือแก้ regression ที่มีหลักฐาน; การเพิ่ม scope
   ต้องบอกว่างานใดจะถูกเลื่อนและบันทึกการตัดสินใจ
4. ทำ dev ก่อน รัน build/test ที่จำเป็นช่วงท้ายรอบ ไม่รัน full suite หลังทุก edit
   งาน geometry เก็บ baseline ก่อนแก้เมื่อยังไม่มีของ code/input ชุดนั้น;
   baseline นี้ไม่ใช่การสั่ง build โลกทั้งใบ
5. ปิดรอบด้วยผลตรวจ + สถานะ + งานถัดไปหนึ่งเรื่อง ถ้า environment ขวาง ให้ระบุ
   ขั้นตอนที่ขวางและเก็บงานนั้นในคิว ไม่ขยาย feature เพื่อเลี่ยงการตรวจ
6. ยอมรับผลเฉพาะ snapshot เดียวกัน: commit หรือ revision + สำเนา diff และ hash,
   input/config fingerprint, flags, product, save, พิกัด, client settings และผู้ตรวจ
   งาน dirty เดิมต้องเก็บไว้ตรวจย้อนกลับได้ ไม่ reset เพื่อให้สถานะดูสะอาด
