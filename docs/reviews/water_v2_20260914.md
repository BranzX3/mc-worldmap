# Water v2 — greenfield compiler, 2026-09-14

สถานะ: implementation ของ scene compiler และ product พร้อมตรวจ; ยังไม่รับรองน้ำในเกม
รอบนี้เริ่มจาก DEM/OSM โดยตรง ไม่ใช้ผลน้ำหรือ shaper/painter เดิม
พัฒนาและรันบนเครื่อง local ไม่มี deploy และยังไม่มี water-v2 ถูกเขียนลงเซฟ

## สิ่งที่เปลี่ยน

- topology คง source identity; router จองพื้นที่และหลบทางน้ำที่จัดไว้แล้ว
  ถ้าหลบไม่ได้ใน corridor ให้ compiler รายงานข้อขัดแย้ง ไม่เชื่อมเส้นเอง
- หน้าตัดส่งต่อผ่านน้ำที่เชื่อมถึงกันเท่านั้น จุดบรรจบแก้ระดับร่วมกัน
  โค้งน้ำที่แตะตัวเองโดยไม่ได้วางแผนถือเป็น topology defect
- ระดับขั้นต่ำส่งข้อกำหนดย้อนขึ้นต้นน้ำก่อนแก้ preference ทะเลสาบที่มี
  ทางออกไม่ถูกทำเป็น sink และขอบ scene ที่เป็นทางเข้าน้ำยังไหลต่อได้
- การจำแนกแอ่งคัดพื้นที่ที่ตลิ่งเก็บระดับ core ไม่ได้ออก แต่ยังต้องปรับปรุง
  บน polygon ที่ลาดต่อเนื่อง ไม่ถือว่า polygon เดียวเป็นทะเลสาบเดียว
- product ระบุระดับ/ความลึก/วัสดุ/พืช/fluid state ทั้งหมด ตัวแปลงบล็อก
  วางตามข้อมูลนั้น ตรวจ section, receiver และไฟล์ที่เปิดอ่านกลับ
- มีคำสั่ง `scenarios` สำหรับ 4 พิกัด พร้อมรายงานและแบบ comment JSON
  ผูกกับ hash ของ code/input/product และไม่ยอมเผยแพร่เมื่อไฟล์เปลี่ยนระหว่างรัน

## งานที่ยังขวาง W2 → W3

1. basin: จำแนกผืนน้ำลาดและแอ่งที่เก็บน้ำได้จากบริบททางเข้า/ออก
   แทนการใช้แถบระดับ DEM เป็น lake หลายแอ่ง
2. topology: แก้ route ที่ยังชนจาก waypoint และการปัดพิกัด การจองเส้นแบบ
   greedy ที่ล้มเหลวไม่ได้พิสูจน์ว่าหาทางแก้ร่วมทั้ง network ไม่ได้
3. supply: กำหนดพฤติกรรมของช่วงราบยาวและ pool จากรูปทรงกับทางออก
   แบบจำลอง surface supply ปัจจุบันยังไม่ใช่การจำลอง vanilla ticks
4. เมื่อ physical gate ผ่านแล้วจึงสร้าง writer ใหม่ที่จัดการ chunk/clear/fill,
   backup/session lock, fluid ticks และ reopen/readback บนเซฟสำเนา
   ก่อนตรวจภาพ/การเดินและน้ำหลัง tick ตามแต่ละพิกัด

ยังไม่เปลี่ยน default pipeline, ไม่รับรอง global/seam และไม่ใช้จำนวน tests
หรือการอ่าน NPZ กลับแทน world readback/visual acceptance
