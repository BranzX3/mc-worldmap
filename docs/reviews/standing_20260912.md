## ปัญหาและการแก้

เดิม patch เลือก mode ของ DEM ภายในกรอบแล้วทำ waterbody component ทั้งก้อน
ให้ราบ แต่ global แยก corridor ของลำน้ำออกก่อน จำแนกแอ่งราบจาก component เต็ม
แล้วเลือกระดับด้วย percentile จึงตรวจ patch แล้วอนุมานผล global ไม่ได้
ที่ lake_mouth มี polygon ลาดชันปนอยู่ การ flatten เป็นระดับ 75 ตัดพื้นได้ 49 บล็อก

รวมขั้นตอนเป็น `prepare_hydrology_context`: สร้าง profiles ทั้งเครือข่าย,
แยก corridor, จำแนกน้ำนิ่งจากผืนน้ำเต็ม และ pin profiles กับระดับแอ่งก่อนตัดกรอบ
ทั้ง default `shape_hydrology_patch` และ `shape_hydrology_global` ใช้ขั้นตอนนี้
ลบการเลือก mode เฉพาะ patch ออกจากตัวขึ้นรูปน้ำนิ่งแล้ว ตัวขั้นล่างรับ
`standing_surface` ที่เตรียมไว้ชัดเจน จึงไม่มีกฎสองชุดให้เลือกโดยเงียบ ๆ

Patch ใช้ context ชั่วคราวและปิด memory mapping ก่อนล้าง directory บน Windows
อ่าน vectors ของ source ครั้งเดียวก่อนวน profiles เพื่อไม่คลาย npz ซ้ำหลายพันครั้ง
ไม่มีการเปลี่ยน input, threshold, น้ำหนัก metric หรือประกาศ gorge exemption

## ข้อจำกัดและงานถัดไป

การจำแนกใหม่นี้ทำให้ patch ใช้ทางสร้างน้ำบน polygon ลาดชันที่ global ใช้อยู่แล้ว
ผลน้ำกว้างที่ไม่มี centerline ใกล้ ๆ อ้าง DEM ท้องถิ่น ต้องตรวจสภาพน้ำจริงหลัง tick
และการเดินริมฝั่งใน world gate ไม่รับรองจากตัวเลขอย่างเดียว
การผ่าน fixture ไม่ได้ยืนยันความเท่ากันของ geometry ทุก tile ทั่วแผนที่

**งานถัดไปหนึ่งเรื่อง:** ตรวจและแก้ขั้นตลิ่งที่ขัดกับการเดิน — เริ่ม hill_junction
ที่ bank excess 5.42% และ lake_mouth ที่ bank climb สูงสุดเพิ่มเป็น 7 บล็อก
เทียบกับ DEM/feature mask และหาพิกัดของขั้นที่เกิดจาก generator ก่อนปรับรูปทรง
ไม่ไถหน้าผาธรรมชาติเพื่อทำคะแนน และไม่ยกเว้น feature โดยไม่มีหลักฐาน
หลังจากนั้นตรวจ regressions เรื่องก้นน้ำ/แอ่งจาก wide-water fallback ก่อน world gate
ยังไม่มี world readback หรือภาพ/การเดินในเกมของ candidate นี้
